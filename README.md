
Cloud Resume on Azure

My resume, built as a cloud application on Microsoft Azure: a static site with automatic deployment, a serverless visitor counter, and the cost, monitoring and governance controls you would expect in a real environment.

Live site: https://gray-forest-02997eb00.2.azurestaticapps.net/

The browser loads the site from Azure Static Web Apps (Free plan, globally distributed).
main.js calls POST /api/visitors.
A serverless Azure Function (Node.js 20) reads the count from Azure Table Storage, adds one, saves it and returns the new number.
Every request is tracked in Application Insights, and failures trigger an email alert.

Lessons learned
Configuration is part of the system. The counter failed until the storage connection string was applied as an environment variable. Checking the HTTP status in DevTools (404 vs 500) showed which layer was broken.
Telemetry has a delay. New Application Insights data can take several minutes to appear.
Policy scope matters. A policy applies only where it is assigned. Supporting resources created automatically by Azure (like a default Log Analytics workspace) can sit outside that scope.
Known limitations and next steps
The counter counts page loads, not unique visitors.
Add automated tests (including accessibility checks) to the pipeline before deployment.
Define the infrastructure as code with Bicep.
Move the Log Analytics workspace into the project resource group so it is covered by the lock and policy.
Add an AI feature with Azure AI Language (sentiment analysis on visitor feedback).
Cost

Static Web Apps (Free) and the Function run at no cost. Table Storage and the failure alert cost cents per month.
